## 1. 핸드오프 요약

### 제품 한 줄 설명

메신저와 이메일에 흩어진 개발 업무를 하나의 팀 보드에 모으고, 업무 상태·담당자·마감일을 한눈에 보여주는 업무 관리 앱입니다.

### MVP에서 반드시 검증할 것

1. 팀원이 로그인 후 자신의 오늘·지연 업무를 즉시 찾을 수 있는가?
2. 팀원이 백로그에서 이번 주 업무를 빠르게 선택할 수 있는가?
3. 칸반 보드만 보고 팀 전체의 현재 진행 상황을 이해할 수 있는가?
4. 업무 상태를 부담 없이 업데이트할 수 있는가?
5. 마감일과 지연 업무를 놓치지 않는가?

### 핵심 상태 흐름

```text
백로그 → 예정 → 진행 → QA → 완료
```

완료된 업무는 기본 보드에서 자동 보관하고, 별도의 완료 업무 보기에서 다시 확인합니다.

## 3. 사용자 역할과 권한

- 팀 설정 조회·수정

- 업무 완료 처리 예외 권한

### 일반 멤버

- 팀 보드 조회
- 백로그 업무 조회
- 이번 주 업무 선택
- 업무 담당자 지정 또는 자신에게 할당
- 업무 상태 변경
- 체크리스트 수정
- 상태 메모 작성
- 댓글 작성

- 자신이 담당한 업무 완료 처리

### 기본 데이터 공개 정책

> 확인 필요: 일반 멤버가 새 업무를 직접 생성할 수 있는지, 리더만 생성할지 최종 결정해야 합니다. 현재 인터뷰에서는 리더가 업무를 등록하고 팀원이 백로그에서 자율적으로 선택하는 흐름을 기본으로 합니다.

## 5. 화면별 요구사항

## 5.1 내 업무 화면

### 목적

로그인 직후 사용자가 자신이 처리해야 할 일을 우선 확인하고, 지연 업무를 놓치지 않도록 합니다.

### 화면 구성

1. 페이지 제목: `내 업무`
2. 요약 영역
   - 지연 업무 수
   - 오늘 마감 업무 수
   - 이번 주 업무 수
3. `지연됨` 섹션
4. `오늘 처리할 업무` 섹션
5. `이번 주 업무` 섹션
6. 필요 시 `전체 내 업무` 섹션

### 정렬

- 지연 업무 최상단
- 마감일 가까운 순
- 마감일 없는 업무는 하단 또는 `마감 없음` 그룹

### 카드 표시 정보

- 업무 제목
- 업무 유형
- 상태
- 담당자 아바타 또는 이름
- 우선순위
- 마감일
- 체크리스트 완료율
- 막힘 표시

### 빈 상태

- 업무가 없을 때: `현재 맡은 업무가 없습니다.`
- 이번 주 업무가 없을 때: `이번 주에 계획된 업무가 없습니다.`
- 지연 업무가 없을 때: `지연된 업무가 없습니다.`

## 5.2 팀 보드 — 칸반 보기

### 목적

팀 전체 업무의 현재 흐름을 한 화면에서 파악합니다.

### 기본 열

1. 백로그
2. 예정
3. 진행
4. QA
5. 완료

### 카드 동작

- 카드를 드래그해 상태 변경
- 카드를 클릭해 업무 상세 열기
- 카드 안에서 우선순위와 마감일 확인
- 체크리스트 완료율 확인
- 막힘 상태 시 시각적 표시

### 카드 원칙

- 핵심 정보만 간결하게 표시
- 긴 설명·댓글·첨부자료는 상세 화면에서 표시
- 완료 열은 기본적으로 접거나 숨길 수 있음
- 완료 업무 자동 보관 후 별도 완료 업무 보기로 이동

### 카드 예시

```text
[기능] 결제 화면 추가
높음 · 예정
김개발
마감 9월 12일
체크리스트 2/5
```

### WIP 표시

진행 열 상단에 다음 정보를 표시합니다.

```text
진행 3 / 권장 한도 3
```

초기 권장 동작:

- 한도 초과 시 경고 표시
- 업무 이동 자체는 막지 않음
- 초과 상태를 관리자와 팀원에게 동일하게 표시

> 구체적인 숫자와 한도 강제 여부는 미확정입니다.

## 5.3 팀 보드 — 리스트 보기

### 목적

업무를 비교·검색·필터링하고, 마감일과 담당자를 빠르게 확인합니다.

### 기본 열

| 열 | 설명 |
|---|---|
| 업무 | 유형 접두사를 포함한 제목 |
| 상태 | 백로그·예정·진행·QA·완료 |
| 담당자 | 담당자 이름 또는 미지정 |
| 우선순위 | 긴급·높음·보통·낮음 |
| 마감일 | 날짜 또는 마감 없음 |
| 체크리스트 | 완료 수/전체 수 |
| 최근 수정 | 마지막 변경 시각 |

### 기본 정렬

- 마감일 가까운 순
- 지연 업무 우선
- 마감일 없는 업무는 하단

### 필터

- 담당자
- 상태
- 우선순위
- 업무 유형
- 마감일
- 이번 주 여부
- 막힘 여부

### 검색

- 제목 검색
- 설명 검색
- 검색 결과에 완료 업무 포함 여부를 선택할 수 있도록 고려

## 5.4 업무 생성

### 빠른 생성

빠른 생성은 제목만 입력해도 저장할 수 있어야 합니다.

```text
업무 제목 입력
[추가]
```

저장 기본값:

- 상태: 백로그
- 담당자: 미지정
- 마감일: 없음
- 우선순위: 보통
- 업무 유형: 기본 유형 또는 미선택

### 상세 생성

다음 정보를 한 번에 입력할 수 있습니다.

- 제목
- 업무 유형
- 설명
- 담당자
- 상태
- 우선순위
- 마감일
- 체크리스트
- 외부 링크
- 첨부파일

### 입력 UX

- 빠른 생성과 상세 생성 모두 지원
- 제목 입력 후 Enter로 빠른 저장 가능
- 상세 입력은 저장 후에도 수정 가능
- 담당자 없이 백로그 저장 가능
- 마감일은 선택 사항

### 제목 안내

업무 유형 접두사를 권장합니다.

```text
[기능] 사용자 프로필 수정
[개선] API 응답 속도 개선
[기술 부채] 인증 코드 정리
```

강제 규칙으로 만들기보다 유형 선택 시 플레이스홀더를 제공합니다.

## 5.5 업무 상세

### 주요 영역 순서

1. 제목 및 업무 유형
2. 상태 변경 컨트롤
3. 담당자·우선순위·마감일
4. 체크리스트
5. 한 줄 상태 메모
6. 막힘 사유
7. 설명
8. 외부 링크
9. 첨부파일
10. 댓글·진행 기록
11. 전체 변경 이력

### 상태 변경

- 드롭다운 또는 상태 버튼 제공
- 담당자가 아닌 사용자도 업무 상태를 변경할 수 있음
- 완료 상태 변경은 담당자만 가능
- 관리자는 예외적으로 완료 처리 가능하도록 권장

### 체크리스트

- 항목 추가·수정·삭제
- 완료 체크
- 순서 변경은 후순위 가능
- 완료율 표시: `2/5`
- 체크리스트가 없으면 완료율을 표시하지 않음

### 상태 메모

한 줄로 현재 상황을 기록합니다.

예시:

- `API 개발 중, 오늘 오후에 1차 완료 예정`
- `QA 환경 데이터 문제로 대기 중`
- `문서 확인 후 구현 시작 예정`

### 막힘 사유

- `막힘` 토글 제공
- 활성화 시 막힘 사유 입력란 표시
- 카드와 내 업무 화면에 막힘 아이콘 표시

### 댓글

- 댓글 목록과 입력창 제공
- 업무 참여자에게 댓글·상태 메모 업데이트 알림
- 댓글의 수정·삭제 권한은 구현 전에 확정

### 변경 이력

모든 변경을 자동 기록합니다.

기록 예시:

```text
김개발님이 상태를 '예정'에서 '진행'으로 변경했습니다.
이리더님이 마감일을 9월 12일로 설정했습니다.
박디자인님이 체크리스트 '모바일 레이아웃 확인'을 완료했습니다.
```

## 5.6 완료 업무 보기

### 목적

완료된 업무를 보드에서 치우면서도 과거 기록을 다시 찾을 수 있게 합니다.

### 기능

- 완료 업무 목록
- 제목 검색
- 담당자·업무 유형·완료 기간 필터
- 업무 상세 열람
- 관리자 또는 권한 있는 사용자의 복구

### 기본 정책

- 완료 즉시 기본 보드에서 숨김
- 데이터를 삭제하지 않음
- 완료 일시와 완료 처리자를 보존

업무 참여자의 정의는 담당자·생성자·댓글 작성자 기준으로 시작하는 것을 권장합니다.

## 6. 주간 계획과 스프린트 처리

### 확정된 운영 방식

- 1주 단위 계획
- 팀원이 백로그에서 이번 주 업무를 자율적으로 선택
- 이번 주 업무를 별도 보기로 확인
- 주간 종료 시 미완료 업무는 다음 주로 자동 이동

### MVP 구현 방식

복잡한 스프린트 엔티티 대신 초기에는 다음 필드로 구현할 수 있습니다.

```text
is_current_week: boolean
week_key: YYYY-WW
```

주간 전환 시:

1. 현재 주의 미완료 업무 조회
2. 다음 주 업무로 자동 이동
3. 완료 업무는 이동하지 않음
4. 기록을 ActivityLog에 남김

### 중복 방지

- 업무 하나는 한 시점에 하나의 주간 계획에만 속함
- 자동 이동 시 이미 다음 주에 있는 업무는 중복 생성하지 않음
- 업무의 ID는 유지하고 주간 속성만 변경

### 추후 확장

- 스프린트 시작·종료 기록
- 업무 계획량과 완료량 비교
- 회고 메모
- 미완료 사유 집계

## 9. 상태 전이 규칙

| 현재 상태 | 다음 상태 | 허용 여부 | 비고 |
|---|---|---:|---|
| 백로그 | 예정 | 허용 | 주간 계획에 넣을 때 사용 가능 |
| 백로그 | 진행 | 허용 | 빠른 착수 시 허용 가능 |
| 예정 | 진행 | 허용 | 개발 시작 |
| 진행 | QA | 허용 | 개발 완료 후 테스트 |

| QA | 진행 | 허용 | 수정이 필요할 때 되돌림 |
| 진행 | 백로그 | 허용 | 계획 취소 또는 재검토 |
| 완료 | 재활성화 | 권한 필요 | 완료 업무 보기에서 복구 |

## 10. 비기능 요구사항

### 반응형

- 데스크톱: 칸반 전체 열을 한 화면에 보여주는 것을 우선
- 모바일: 칸반을 가로 스크롤 또는 상태별 탭으로 제공
- 업무 상세는 모바일에서 전체 화면 패널 또는 페이지로 표시

### 성능

- 내 업무 화면의 핵심 목록을 빠르게 표시
- 칸반 이동 후 낙관적 UI 업데이트 고려
- 대용량 파일은 업로드 진행률 제공
- 검색 입력은 디바운스 처리

### 접근성

- 드래그 앤 드롭의 키보드 대체 동작 제공
- 색상만으로 상태·우선순위를 구분하지 않음
- 상태와 우선순위에 텍스트·아이콘 병행
- 버튼에 명확한 레이블 제공
- 모바일 터치 영역 충분히 확보

### 보안

- 팀 간 데이터 접근 분리
- 모든 업무·파일 조회 시 팀 멤버 권한 검증
- 초대 링크 만료·재생성 정책 필요
- 파일 다운로드 권한 검증
- 업로드 파일 확장자·크기 제한
- HTML·스크립트가 댓글이나 설명에서 실행되지 않도록 처리
- 변경 이력은 일반 사용자가 임의로 수정하지 못하도록 처리

### 데이터 보존

- 완료 업무는 삭제하지 않고 보관
- 삭제 정책과 복구 기간은 별도 확정
- ActivityLog는 업무의 변경 추적을 위해 보존

## 16. 제품 검증 시나리오

### 시나리오 A — 5분 안에 업무 등록

**목표:** 리더가 메신저에서 받은 요청을 앱에 빠르게 기록할 수 있는지 확인

1. 로그인
2. 새 업무 추가
3. 제목 입력
4. 유형 선택
5. 설명과 링크 추가
6. 담당자 없이 백로그 저장

성공 기준:

- 처음 사용하는 사용자도 안내 없이 완료
- 제목만으로도 저장 가능
- 저장 후 보드에서 즉시 확인

### 시나리오 B — 팀원이 이번 주 업무 선택

**목표:** 팀원이 리더의 별도 배정 없이 스스로 업무를 선택할 수 있는지 확인

1. 백로그 확인
2. 업무 상세 열기
3. 자신을 담당자로 지정
4. 이번 주 업무로 표시
5. 예정 상태로 이동

성공 기준:

- 현재 맡은 업무가 내 업무 화면에 표시
- 다른 팀원이 변경 내용을 확인 가능
- 중복 담당 또는 중복 주간 계획이 발생하지 않음

### 시나리오 C — 진행 상황 확인

**목표:** 팀원이 별도 질문 없이 업무 현황을 파악할 수 있는지 확인

1. 팀 보드 열기
2. 진행·QA 열 확인
3. 카드의 담당자·마감일·우선순위 확인
4. 업무 상세에서 체크리스트와 상태 메모 확인
5. 변경 이력에서 최근 업데이트 확인

성공 기준:

- 누가 무엇을 하는지 30초 안에 파악
- 막힌 업무와 지연 업무를 식별
- 마지막 업데이트 시점을 확인

### 시나리오 D — 주간 전환

**목표:** 주간 계획이 끊김 없이 이어지는지 확인

1. 주간 종료 시점 도달
2. 미완료 업무 조회
3. 다음 주 업무로 자동 이동
4. 완료 업무는 이동하지 않음
5. 변경 이력 확인

성공 기준:

- 업무가 중복 생성되지 않음
- 담당자·체크리스트·댓글·링크가 유지됨
- 팀원이 다음 주 업무에서 즉시 확인 가능

## 18. 완료 정의(Definition of Done)

MVP는 다음 조건을 모두 만족해야 출시 후보로 봅니다.

- [ ] 팀원이 Google 로그인으로 진입할 수 있음
- [ ] 초대 링크로 팀에 참여할 수 있음
- [ ] 하나의 팀 보드에서 업무를 생성·수정할 수 있음
- [ ] 칸반과 리스트를 모두 사용할 수 있음
- [ ] 드래그로 업무 상태를 바꿀 수 있음
- [ ] 내 업무 화면에서 오늘·지연 업무가 먼저 보임
- [ ] 체크리스트 완료율이 정확함
- [ ] 마감일 없는 업무를 허용함
- [ ] 마감 하루 전 알림이 작동함
- [ ] 주요 변경 이력이 남음
- [ ] 완료 업무가 자동 보관되고 다시 검색 가능함
- [ ] 외부 링크와 파일을 업무에 연결할 수 있음
- [ ] 팀원 간 데이터가 분리됨
- [ ] 모바일 브라우저에서 핵심 흐름을 수행할 수 있음
- [ ] 빈 상태·오류 상태가 정의되어 있음
- [ ] 실제 팀원 2명 이상이 업무 등록부터 완료까지 수행함
- [ ] 1주간 실제 업무로 사용 후 치명적인 사용성 문제가 없음

## 19. 오픈 질문

다음 질문은 다음 인터뷰 또는 구현 전 결정 회의에서 확인합니다.

1. WIP 한도 숫자는 얼마로 시작할 것인가?
2. WIP 한도를 `진행`에만 적용할 것인가, `QA`에도 적용할 것인가?
3. 일반 멤버가 새 업무를 만들 수 있는가?
4. 주간 시작 요일은 월요일인가?
5. 주간 전환은 자동 작업으로 처리할 것인가?
6. QA 담당자를 별도로 지정할 것인가?
7. 버그·장애 유형을 MVP에서 보여줄 것인가?
8. 댓글 알림의 참여자 범위를 어떻게 정의할 것인가?
9. 파일 최대 크기와 허용 확장자는 무엇인가?
10. 완료 업무를 얼마 동안 보관할 것인가?
11. 삭제 대신 보관만 허용할 것인가?
12. Google Workspace 도메인 제한이 필요한가?
13. 회고 메모나 주간 요약이 필요한가?
14. Slack·Teams 중 우선 연동할 서비스가 있는가?

## 20. 다음 실행 순서

1. 본 문서의 오픈 질문을 제품 담당자와 확정한다.
2. 실제 업무 샘플을 수집해 상태·필드·유형을 검증한다.

4. 업무 생성·상태 변경·완료의 핵심 프로토타입을 만든다.

7. P0 범위로 구현한다.
8. QA 체크리스트를 실행한다.
9. 1주간 실제 팀 업무로 운영한다.
10. 사용 데이터와 인터뷰를 바탕으로 P1 우선순위를 재조정한다.
