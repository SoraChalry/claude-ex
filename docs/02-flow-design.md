# 02. 사용 흐름 · 화면 설계

> 선택된 시안: A — 사이드바 + 넓은 칸반

## 1. 핵심 시나리오

### S1. 아침에 오늘 업무 계획 세우기

**언제:** 하루 업무를 시작하며 오늘 처리할 업무를 정리할 때

**흐름**

1. `내 업무` 요약에서 지연·오늘·이번 주 업무를 확인한다.
2. `새 업무` 버튼으로 제목, 유형, 설명을 입력한다.
3. 담당자와 우선순위, 마감일을 지정한다.
4. 업무를 `예정` 또는 `진행` 상태로 옮긴다.
5. 카드에서 오늘 처리할 업무와 팀 내 담당자를 확인한다.

**인사이트:** 빠른 등록보다 계획 정보 입력이 중요하므로 생성 화면에서 핵심 메타데이터를 함께 설정한다.

### S2. 팀 보드에서 진행 상황 빠르게 파악하기

**언제:** 업무 중간에 별도 질문 없이 팀 전체 진행 상황을 확인할 때

**흐름**

1. `팀 보드`에서 5개 상태 열을 훑는다.
2. 카드의 담당자·우선순위·마감일을 비교한다.
3. 지연되거나 막힌 카드를 시각적으로 찾는다.
4. 필요한 카드를 클릭해 상세 패널을 연다.
5. 막힘 사유를 확인하고 상태 또는 업무 정보를 변경한다.

**인사이트:** 카드에 정보를 과도하게 넣지 않으면서도 핵심 상황 정보는 상세 화면을 열지 않고 보여준다.

## 2. 설계 원칙

| 원칙 | 내용 | 근거 |
|---|---|---|
| P1. 계획 우선 | 새 업무 생성 시 담당자·우선순위·마감일을 자연스럽게 입력한다. | S1 |
| P2. 30초 파악 | 카드에 상태·담당자·마감일·우선순위·막힘 여부를 텍스트와 아이콘으로 함께 표시한다. | S2 |
| P3. 점진적 공개 | 제목과 핵심 메타데이터는 카드에, 설명·막힘 사유·편집 필드는 상세 패널에 둔다. | S1, S2 |
| P4. 흐름 유지 | 상세 패널을 닫지 않고도 카드 이동과 주요 상태 변경을 수행한다. | S1, S2 |
| P5. 모바일 연속성 | 5개 열 구조를 유지하고 모바일에서는 가로 스크롤로 탐색한다. | S1, S2 |

## 3. 화면 구조 — 화면 목록과 이동 흐름

### 화면 목록

- **앱 셸:** 사이드바, 상단 바, 본문 영역
- **내 업무:** 지연·오늘·이번 주 요약과 담당 업무 목록
- **팀 보드:** 백로그·예정·진행·QA·완료 칸반 열
- **업무 생성:** 제목과 핵심 계획 정보를 입력하는 모달 또는 패널
- **업무 상세:** 카드의 상세 정보와 편집 컨트롤을 제공하는 우측 패널

### 이동 흐름

```text
앱 진입
  ├─ 내 업무 요약 확인
  ├─ 새 업무 계획 → 업무 생성 → 보드의 예정 열
  └─ 팀 보드 → 카드 클릭 → 상세 패널 → 저장
```

## 4. 컴포넌트 명세

| Sidebar | `내 업무`, `팀 보드`, `완료 업무` 내비게이션. 이번 MVP에서는 완료 업무 항목을 보드의 완료 열로 연결한다. |
| TopBar | 현재 팀명, 검색 자리, 알림 자리, 현재 사용자 메뉴를 표시한다. |
| SummaryStrip | 지연·오늘·이번 주 업무 수를 숫자와 텍스트로 보여준다. |
| QuickCreate | 제목·유형·설명·담당자·우선순위·마감일을 입력하고 저장한다. |
| KanbanBoard | 5개 상태 열을 가로로 배치한다. 모바일에서는 보드 전체가 가로 스크롤된다. |
| KanbanColumn | 상태명, 카드 수, 진행 열의 WIP 권장 한도 표시, 빈 상태를 제공한다. |
| TaskCard | 제목, 유형, 담당자, 우선순위, 마감일, 체크리스트 진행률, 막힘 상태를 표시한다. 클릭하면 상세 패널을 연다. |
| TaskDetailPanel | 업무 메타데이터 편집, 설명, 막힘 토글과 사유, 상태 변경을 제공한다. |

## 5. 상태 & 인터랙션 규칙

- 새 업무의 기본 상태는 `백로그`이며, 계획 입력을 완료하면 `예정`으로 선택할 수 있다.
- 카드 상태 변경은 드래그 앤 드롭 또는 상세 패널의 상태 선택으로 수행한다.
- 업무는 `백로그`, `예정`, `진행`, `QA`, `완료` 중 하나의 상태를 가진다.
- 지연 업무는 마감일이 오늘보다 이전이고 완료가 아닌 업무로 계산한다.
- 오늘 업무는 마감일이 오늘인 업무, 이번 주 업무는 현재 주에 해당하는 마감 업무로 계산한다.
- 막힘 토글이 켜지면 카드에 `막힘` 텍스트와 아이콘을 함께 표시하고, 사유를 상세 패널에 노출한다.
- 저장 성공 시 현재 보드와 요약을 즉시 갱신하고 `localStorage`에 저장한다.
- 빈 열에는 다음 행동을 안내하는 빈 상태와 `업무 추가` 동작을 제공한다.
- 모바일에서는 열 너비를 유지해 가로 스크롤을 허용하고, 카드 터치 영역을 충분히 확보한다.

## 6. 색상 토큰 · 반응형 · 접근성

### 색상 토큰

- 배경: 밝은 중성색
- 본문: 짙은 슬레이트
- 브랜드: 차분한 네이비
- 상태: 상태별 포인트 색상 + 상태명 텍스트
- 우선순위: 긴급·높음·보통·낮음의 색상 + 레이블
- 지연·막힘: 주의를 주되 과도한 경고감을 피하는 앰버 계열

색상만으로 상태·우선순위를 구분하지 않고 텍스트와 아이콘을 병행한다.

### 반응형

- 데스크톱: 사이드바를 고정하고 5개 칸반 열을 넓게 표시한다.
- 태블릿: 사이드바 너비를 줄이고 보드 가로 스크롤을 허용한다.
- 모바일: 사이드바를 축소하거나 상단 메뉴로 전환하고, 칸반 열은 가로 스크롤한다.
- 업무 상세 패널은 모바일에서 화면 폭에 맞는 전체 폭 패널로 표시한다.

### 접근성

- 모든 아이콘 버튼에 accessible label을 제공한다.
- 드래그 외에도 상세 패널의 상태 선택으로 키보드 상태 변경을 지원한다.
- 포커스 표시와 충분한 터치 영역을 제공한다.
- 빈 상태·저장 오류·검색 결과 없음 상태를 텍스트로 안내한다.
