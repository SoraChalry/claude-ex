# 03. 구현 계획

## 1. 기술 구조

### 스택 확정

| 항목 | 결정 |
|---|---|
| UI | React + TypeScript |
| 빌드 | Vite |
| 스타일 | CSS 모듈 없이 컴포넌트 범위 CSS 또는 단일 스타일시트 (가정) |
| 저장 | `localStorage` 어댑터 |
| 테스트 | 프로젝트 기본 테스트 도구가 있으면 활용하고, 없으면 build와 브라우저 수동 검증을 우선한다 (가정) |
| 드래그 | 브라우저 기본 drag/drop API로 시작해 의존성을 최소화한다 (가정) |

### 폴더 구조

```text
src/
├── components/
│   ├── layout/
│   ├── board/
│   ├── task/
│   └── shared/
├── data/
├── hooks/
├── types/
├── utils/
└── styles/
```

### 상태 흐름

```text
TaskCard dragstart / 상세 상태 선택
        ↓
보드의 상태 변경 핸들러
        ↓
Task 목록의 해당 task.status 갱신
        ↓
localStorage 저장 + 보드/요약 재계산
        ↓
카드와 SummaryStrip 즉시 렌더링
```

## 3. 마일스톤 상세

## M1 — 앱 셸과 데이터 기반 (25~35분)

**목표**: 앱을 실행하고 샘플 팀원·업무 데이터가 타입을 통해 화면에 전달되는 기반을 만든다.

**할 일**

- [ ] 기존 프로젝트 구조 확인 및 React + TypeScript + Vite 최소 실행 구조 구성
- [ ] Task·TeamMember·Status·Priority 타입 정의
- [ ] 핸드오프 상태 5개와 샘플 팀원·샘플 업무 데이터 정의
- [ ] 사이드바·상단 바·본문 레이아웃 뼈대 구현

**완료 조건**

- [ ] 앱이 개발 서버에서 실행된다.
- [ ] 시안 A의 사이드바와 상단 바 구조가 보인다.

**검증 방법**

- [ ] 자동: `npm run build`
- [ ] 수동: 앱을 열어 샘플 데이터와 기본 레이아웃 확인

**중단 가능 지점**: 데이터와 레이아웃 기반이 갖춰진 실행 가능한 앱.

## M2 — 칸반 핵심 CRUD (30~40분)

**목표**: 5개 상태 열에서 업무를 생성하고 상태를 변경한다.

**할 일**

- [ ] 5개 KanbanColumn 렌더링
- [ ] 제목 기반 빠른 업무 생성 및 빈 입력 방지
- [ ] 카드 클릭 이벤트와 카드 삭제 동작
- [ ] 기본 drag/drop과 상세 상태 선택을 위한 상태 변경 핸들러

**완료 조건**

- [ ] 새 업무가 백로그에 즉시 나타난다.
- [ ] 카드를 다른 열로 옮기면 해당 상태가 바뀐다.
- [ ] 카드가 상태·제목을 식별 가능한 텍스트로 표시한다.

**검증 방법**

- [ ] 자동: `npm run build`
- [ ] 수동: 업무 생성, 열 간 이동, 삭제를 반복 확인

**중단 가능 지점**: 생성·이동 가능한 기본 칸반.

## M3 — 업무 상세 편집 (25~35분)

**목표**: 카드의 계획 정보를 상세 패널에서 편집한다.

**할 일**

- [ ] 우측 TaskDetailPanel 구현
- [ ] 담당자·우선순위·마감일·설명 입력
- [ ] 막힘 토글과 막힘 사유 입력
- [ ] 저장·닫기·상태 변경 인터랙션 연결

**완료 조건**

- [ ] 카드 클릭으로 상세 패널이 열린다.
- [ ] 저장한 메타데이터가 카드와 상세 패널에 반영된다.
- [ ] 업무 계획 시 핵심 정보를 한 흐름 안에서 입력할 수 있다.

**검증 방법**

- [ ] 자동: `npm run build`
- [ ] 수동: S1 흐름으로 업무 생성 후 담당자·우선순위·마감일·막힘 저장

**중단 가능 지점**: 핵심 계획 정보를 갖춘 업무 보드.

## M4 — 내 업무 요약 (20~30분)

**목표**: 현재 사용자 기준으로 지연·오늘·이번 주 업무를 즉시 확인한다.

**할 일**

- [ ] SummaryStrip에 지연·오늘·이번 주 수치 계산
- [ ] `내 업무`와 `팀 보드` 보기 전환
- [ ] 내 업무 화면의 섹션별 카드 목록과 빈 상태
- [ ] 날짜 기준 유틸리티 구현

**완료 조건**

- [ ] 지연 업무가 최상단에 구분된다.
- [ ] 오늘·이번 주 업무 수가 카드 데이터와 일치한다.
- [ ] 담당 업무가 없을 때 안내 문구가 보인다.

**검증 방법**

- [ ] 자동: `npm run build`
- [ ] 수동: 샘플 날짜와 담당자를 바꿔 S1 요약 확인

**중단 가능 지점**: 계획과 개인 업무 확인이 가능한 앱.

## M5 — 30초 파악 UX (20~30분)

**목표**: 카드만 훑어도 팀의 현재 상황을 파악할 수 있게 한다.

**할 일**

- [ ] 카드에 담당자·마감일·우선순위 배지 표시
- [ ] 지연 업무와 막힘 상태 강조
- [ ] 긴급·높음·보통·낮음 텍스트 레이블과 아이콘/색상 적용
- [ ] 진행 열의 카드 수와 권장 WIP 한도 표시 (가정: 한도 3)

**완료 조건**

- [ ] 30초 안에 상태·담당자·마감일·우선순위·막힘 여부를 읽을 수 있다.
- [ ] 색상을 끄거나 구분하기 어려워도 텍스트로 상태와 우선순위를 식별할 수 있다.
- [ ] 지연·막힘이 명확하되 과도한 경고색으로 화면을 지배하지 않는다.

**검증 방법**

- [ ] 자동: `npm run build`
- [ ] 수동: S2 흐름으로 보드를 훑고 지연·막힘 카드 식별

**중단 가능 지점**: 핵심 차별점이 체감되는 보드.

## M6 — 반응형·영속성·빈 상태 (20~30분)

**목표**: 데스크톱과 모바일에서 안정적으로 사용하고 새로고침 후에도 업무를 보존한다.

**할 일**

- [ ] localStorage load/save와 초기 데이터 fallback 구현
- [ ] 데스크톱 사이드바·보드 레이아웃 스타일링
- [ ] 모바일 가로 스크롤·터치 영역·상세 패널 반응형 처리
- [ ] 빈 열·검색 결과 없음·저장 오류 기본 상태 처리

**완료 조건**

- [ ] 새로고침 후 생성·편집·이동 결과가 유지된다.
- [ ] 모바일에서 5개 열을 가로 스크롤할 수 있다.
- [ ] 좁은 화면에서 카드와 주요 버튼이 겹치지 않는다.

**검증 방법**

- [ ] 자동: `npm run build`
- [ ] 수동: 데스크톱·모바일 뷰포트와 새로고침 확인

**중단 가능 지점**: 실제 사용 가능한 반응형 MVP.

## M7 — 최종 QA·마감 (20~30분)

**할 일**

- [ ] 한글 IME 입력, 빈 입력, 긴 제목, localStorage 데이터 확인
- [ ] README와 `.gitignore` 점검
- [ ] 불필요한 디버그 출력 제거

**완료 조건**

- [ ] S1 업무 계획과 S2 30초 파악 흐름이 완료된다.
- [ ] 차별점인 30초 상황 파악이 카드 UI에서 체감된다.
- [ ] 모바일·빈 상태·영속성 검증을 통과한다.

**검증 방법**

- [ ] 자동: 프로젝트에서 제공하는 `npm test`, `npm run build`, `npm run lint` 실행
- [ ] 수동: 최종 QA 체크리스트 전체 수행

## 4. 차별점 반영 위치

`01-requirements.md`의 차별점인 “카드를 훑는 30초 안에 상태·담당자·마감일·우선순위와 지연·막힘 여부를 함께 파악”은 다음에 반영한다.

- M5 할 일: 카드 핵심 메타데이터, 지연·막힘 강조, 텍스트·아이콘 표시
- M5 완료 조건: 30초 안에 핵심 정보를 읽고 색상 없이도 식별 가능
- M7 검증: S2에서 실제로 지연·막힘 카드를 식별

## 5. v2로 미루는 것

| 항목 | 이유 |
|---|---|
| Google 로그인·팀 초대·권한 | 서버와 인증 설정이 필요해 반나절 범위를 초과 |
| 원격 DB·실시간 동기화 | localStorage 프로토타입 검증 이후 확정 |
| 댓글·파일·외부 링크·변경 이력 | 상세 협업 기능은 핵심 칸반 이후 확장 |
| 리스트 보기·완료 업무 보관 화면 | 이번 버전은 칸반 핵심 흐름에 집중 |
| 검색·고급 필터·푸시 알림 | 데이터 규모와 실제 사용 패턴 확인 후 추가 |
| 주간 자동 이동·WIP 설정 UI | 운영 규칙 확정 후 추가 |

## 6. 가정 목록 (최종)

- 기존 앱 코드가 없어 React + TypeScript + Vite로 시작한다.
- 인증 없이 샘플 팀원과 가상 현재 사용자 `나`를 사용한다.
- 데이터는 단일 브라우저의 localStorage에 저장한다.
- 새 업무는 계획 정보를 입력해 기본 `예정` 상태로 저장할 수 있게 한다.
- 완료 열은 보드에 표시하고 별도 보관 화면은 만들지 않는다.
- 핸드오프의 5개 상태 이름을 그대로 사용한다.
- 초기 WIP 권장 한도는 `진행 3`으로 표시하고 이동을 차단하지 않는다.
- 기본 드래그는 브라우저 API로 구현한다.
