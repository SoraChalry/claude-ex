# 01. 요구사항

## 1. 개요

| 항목 | 값 |
|---|---|
| 한 줄 정의 | 소규모 팀이 업무를 상태·담당자별로 관리하고 칸반 보드에서 진행 상황을 즉시 파악하는 반응형 업무 관리 앱 |
| 목적 | 핸드오프 문서의 핵심 칸반 흐름을 검증하는 팀 업무 프로토타입 (가정) |
| 디바이스 | 데스크톱 우선 반응형 웹 |
| 스택 | React + TypeScript + Vite (가정) |
| 저장 | 브라우저 localStorage (가정) |
| 시간 예산 | 반나절 |

## 2. 주 사용자와 사용 상황

- 누구: 1~5명의 개발·제품팀 구성원과 팀 리더
- 얼마나 자주: 업무를 등록하거나 상태를 확인할 때 수시로, 최소 하루 한 번
- 언제·어디서: 업무 요청을 받은 직후 백로그에 기록하거나, 보드를 열어 팀 진행 상황을 확인할 때
- 다른 상황: 모바일에서는 담당 업무와 마감 정보를 빠르게 확인하고 상태를 바꾼다 (가정)

## 3. 핵심 문제

업무가 메신저와 이메일에 흩어져 있으면 누가 무엇을 하고 있는지와 어떤 업무가 막혔는지 즉시 파악하기 어렵다. 팀 보드 하나에서 상태·담당자·마감 정보를 확인하고 빠르게 갱신할 수 있어야 한다.

## 4. 핵심 기능

1. 백로그·예정·진행·QA·완료 5개 열을 가진 칸반 보드
2. 제목만 입력하는 빠른 업무 생성과 카드 드래그를 통한 상태 변경
3. 업무 상세에서 담당자, 우선순위, 마감일, 설명, 막힘 상태를 조회·수정
4. 내 업무 요약에서 지연·오늘·이번 주 담당 업무를 확인
5. 샘플 팀원 고정 데이터를 사용하고 변경 내용을 localStorage에 보존

## 5. 데이터 모델

| 엔티티 | 필드 | 비고 |
|---|---|---|
| Task | id, title, description, status, assigneeId, priority, dueDate, isBlocked, blockedReason, createdAt, updatedAt | 보드 카드의 핵심 단위 |
| TeamMember | id, name, initials, role | 초기에는 샘플 팀원 고정 |

## 6. 차별점

> 카드를 훑는 30초 안에 상태·담당자·마감일·우선순위와 지연·막힘 여부를 함께 파악할 수 있게 한다.

## 7. 범위 제외 (Out of Scope)

- Google 로그인, 팀 초대, 서버·원격 데이터베이스
- 댓글, 파일 업로드, 외부 링크, 변경 이력, 푸시·이메일 알림
- 리스트 보기, 완료 업무 별도 보관 화면, 주간 자동 전환
- 실제 드래그 앤 드롭 라이브러리 도입 없이 구현 가능한 범위를 넘는 고급 권한·WIP 설정

## 8. 완료 기준 (Definition of Done)

- 5개 상태 열과 카드가 데스크톱에서 한눈에 보인다.
- 제목만으로 새 업무를 백로그에 추가할 수 있다.
- 카드를 다른 상태 열로 이동할 수 있고 새로고침 후에도 유지된다.
- 상세 패널에서 핵심 업무 정보를 수정할 수 있다.
- 내 업무 요약이 지연·오늘·이번 주 업무를 구분해 보여준다.
- 카드에서 상태·담당자·마감일·우선순위·진행률/막힘 정보를 색상만이 아닌 텍스트와 함께 확인할 수 있다.
- 모바일 화면에서 보드를 가로 스크롤하거나 상태별로 탐색할 수 있다.
- 빈 상태와 기본 오류 상황이 무너지지 않는다.

## 가정 목록

- 별도 기존 앱 코드가 없으므로 React + TypeScript + Vite로 시작한다.
- 인증 없이 샘플 팀원과 가상 현재 사용자 `나`를 사용한다.
- 데이터는 단일 브라우저의 localStorage에 저장한다.
- 빠른 생성은 제목만 저장하고, 상세 정보는 생성 후 패널에서 수정한다.
- 완료 열은 이번 반나절 MVP에서 보드에 표시하되, 별도 보관 화면은 만들지 않는다.
- 핸드오프의 5개 상태 이름을 그대로 사용한다.
